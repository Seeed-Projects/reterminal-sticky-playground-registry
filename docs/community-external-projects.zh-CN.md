# 社区外链项目

[English](community-external-projects.md) · [固件贡献指南](contributing-firmware.zh-CN.md)

## 适用范围与准入条件

社区外链卡片会在新标签页打开作者的网站。项目需要为 reTerminal Sticky 提供明确、
可以复现的功能，例如按设备生成固件的安装平台，或为 Sticky 阅读器准备文件的网页工具。
目标地址直接进入工具、安装流程或该项目的专用使用说明。

申请者需要解释为什么无法提供可用的 `.bin`，以及网页为什么是产品使用过程的一部分。
例如，网页转换工具的产物是转换后的阅读文件，程序运行在浏览器中；应说明这个关系，
并写明 Sticky 需要安装哪款阅读固件。个性化安装平台则应说明生成了哪些配置、在哪里处理。

卡片简介、外链交付原因和使用流程应说明项目对 Sticky 的实际帮助，方便维护者判断
目标网站是否提供了具体功能，并审核其跳转、下载和使用条件。

## 提交文件与字段

在 `firmwares/<id>/` 中提交 `firmware.json`、`README.md` 和 `assets/` 下的真实设备
照片或截图。审核期间使用 `catalogSection: "draft"`；完成审核后使用
`group: "community"`、`catalogSection: "community"`、适用的 `category` 和
`mode: "external"`。外链路径保留作者、项目源码地址 `source.url`、说明文档和反馈入口。
编译配置与二进制交付字段用于 `flash` 路径。可以在 Firmware 页面的「用表单提交」中
选择「外链项目」（英文界面为 **External project**），也可以自行准备文件后提交 PR。

## 使用官网表单申请

1. 在 Firmware 页面点击「用表单提交」，选择「外链项目」。表单语言跟随网站导航栏的语言切换。
2. 填写项目名称、分类、简介、源码许可证、项目主页和作者，上传真实 Sticky 照片。
   图片支持 PNG、JPEG、WebP，最大 5 MB。
3. 填写准确的目标地址，以及下表中的交付原因、使用流程和使用条件。
   固件版本与二进制上传属于刷写模式。
4. 确认审核要求，完成人机验证后提交。服务生成社区 `draft` 条目，包含元数据、
   README 和照片；PR 中同时列出完整申请与维护者审核清单。
5. 通过返回的 PR 链接跟进审核。维护者核实流程并批准发布后，将 `catalogSection`
   改为 `community`。

`external` 包含 `label`（1–60 字符）、`url`（HTTPS）、`description`（1–400 字符）
及 `submission`。交付原因和使用流程各需 20–2000 字符，使用条件支持 1–2000 字符，
可以简短填写“无需”。公开卡片信息使用英文。

| 字段 | 申请者需要说明的内容 |
| --- | --- |
| `hostingReason` | 为什么无法提供可用的 `.bin`，为什么必须通过外部网站使用 |
| `userFlow` | 从打开网页到 Sticky 上出现结果的完整操作，前置固件、配件、输入文件和预期现象 |
| `siteRequirements` | 账号、费用、浏览器或设备权限、软件安装、收集或上传的数据、第三方服务；无需的项目也明确说明 |

README 说明操作流程、维护联系方式、准确的目标地址和使用条件。
PR 中也完整填写 **External community project application**，方便逐项审核。
申请字段与条目一起保存，后续修改时可以对比前后差异。

## 审核与发布

1. 安装 Node.js 20 或更新版本，在仓库根目录运行 `npm test`、`npm run validate`。
   自动校验检查字段、申请资料完整性、HTTPS 地址和本地图片等内容。
2. 自动审核评论集中展示目标地址与域名、交付原因、使用流程、使用条件、预览图和
   链接检查结果。修改已有外链时，评论会同时列出旧地址。外链发生跳转时，检查器列出
   跳转地址交由人工核实。HTTP 成功仅表示能访问。
3. 维护者打开完整使用流程，检查跳转、下载、权限和数据处理。
   需要账号或付费的步骤应提供足以完成审核的说明。
4. 项目与目标网站一起审核。完成审核后，将 `catalogSection` 改为
   `community`。卡片显示“外部网站”标识和目标域名，主按钮打开审核过的地址。
   安装次数仅统计在 Sticky 网站完成的安装。

## 后续维护

目标网址、域名归属、项目用途、权限、费用或数据处理方式变化时，提交新 PR，更新申请
资料。外链项目转为站内安装时，按固件贡献指南补齐完整固件包和测试记录。

作者负责维护服务和有效的反馈入口。遇到地址不可用、异常下载、疑似入侵、用途转为推广
或使用流程发生实质变化时，维护者可将卡片调整为 `draft`，核实并重新审核后恢复展示。
